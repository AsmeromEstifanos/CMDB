# CI/CD Runbook: GitHub Actions to cPanel

This document describes the current CI/CD setup for this repository.
It is the authoritative reference for how production builds are created and deployed to cPanel.

## 1. Current Production Topology

The application is deployed as a React single-page app under the `/cmdb/` subpath of the main site.

Current assumptions:

- Public URL: `https://sol-ventures.com/cmdb/`
- Hosting model: static build generated by `react-scripts`
- Deploy target on cPanel: `public_html/cmdb`
- Transfer protocol: explicit FTPS on port `21`
- GitHub workflow file: `.github/workflows/deploy-cpanel.yml`
- Apache rewrite file: `public/.htaccess`

Important routing detail:

- The app is built with `PUBLIC_URL=/cmdb`
- React routes are already defined under `/cmdb/*`
- Apache rewrites unknown `/cmdb/*` requests back to `/cmdb/index.html`

## 2. Scope of the Current Pipeline

This is currently a deploy pipeline, not a full multi-stage release pipeline.

What it does:

- Runs on push to `main`
- Can also be started manually with `workflow_dispatch`
- Installs dependencies with `npm ci`
- Builds the production app
- Uploads the contents of `build/` to cPanel via FTPS

What it does not currently do:

- Run unit tests as a required gate
- Run lint as a required gate
- Build preview environments for pull requests
- Promote across separate staging and production environments
- Use GitHub Environments or approval rules

## 3. Files That Make Up CI/CD

### Workflow

Path: `.github/workflows/deploy-cpanel.yml`

Responsibilities:

- Validates deploy secrets are present
- Builds the app with the required `REACT_APP_*` environment variables
- Deploys `build/` to cPanel with `SamKirkland/FTP-Deploy-Action`

### Rewrite rules

Path: `public/.htaccess`

Responsibilities:

- Enables SPA routing under `/cmdb/`
- Sends unknown subpath requests back to `/cmdb/index.html`

### Build scripts

Path: `package.json`

Relevant scripts:

- `npm run build`
- `npm run tailwind:build`

The production build is created by:

```bash
npm run tailwind:build && react-scripts build
```

## 4. Triggering Deployment

The workflow deploys automatically when code is pushed to `main`.

It can also be run manually from GitHub:

1. Open `Actions`
2. Open `Deploy to cPanel`
3. Click `Run workflow`

Use manual runs when:

- secrets were updated
- the same commit needs to be redeployed
- hosting configuration changed and you want to verify deployment again

## 5. GitHub Configuration

Use repository secrets, not `.env` files in the repository and not GitHub Environments.

Path in GitHub:

`Repository Settings > Secrets and variables > Actions > Repository secrets`

### 5.1 cPanel deploy secrets

These secrets are required for the FTPS upload itself.

- `CPANEL_SERVER`
  Use the direct FTPS hostname. In the current working setup this should be the origin host from the hosting panel, not the Cloudflare-fronted `ftp.sol-ventures.com` hostname.
  Current working value: `s4377.lon1.stableserver.net`

- `CPANEL_USERNAME`
  The FTP account username created in cPanel.

- `CPANEL_PASSWORD`
  The password for that FTP account.

- `CPANEL_PORT`
  Current value: `21`

- `CPANEL_SERVER_DIR`
  The remote directory relative to the FTP login root.
  Because the FTP account is scoped directly to `public_html/cmdb`, the current working value is `/`.

### 5.2 React build-time secrets

These are copied from the local `.env` file and injected during the GitHub Actions build.
Because this app uses `react-scripts`, only `REACT_APP_*` values matter for the deployed bundle.

Required repository secrets:

- `REACT_APP_AZURE_CLIENT_ID`
- `REACT_APP_AZURE_AUTHORITY`
- `REACT_APP_SHAREPOINT_SITE_URL`
- `REACT_APP_ASSET_DRIVE_ID`
- `REACT_APP_REDIRECT_URI`

Current application expectations:

- `REACT_APP_REDIRECT_URI` should match the deployed URL under `/cmdb`
- local `.env` may also contain `VITE_*` values, but they are not used by the current build pipeline

## 6. Local .env Versus GitHub Secrets

Local development and GitHub deployment are separate concerns.

### Local development

Use `.env` locally for development and manual local builds.
The file is already ignored by Git.

### GitHub Actions

GitHub cannot read your local `.env` file.
If a value is required during the GitHub build, it must exist as a repository secret.

Do not:

- commit `.env`
- paste secrets into the workflow file
- create a GitHub Environment unless the workflow is explicitly updated to use one

## 7. cPanel Setup

### FTP account

A dedicated FTP account should be created in cPanel for deployment.

Recommended setup:

- Account is restricted to `public_html/cmdb`
- Quota can be unlimited or a reasonable cap
- Use a dedicated password that can be rotated independently

Why this matters:

- limits deploy access to the application folder only
- allows `CPANEL_SERVER_DIR=/`
- avoids accidental writes outside the app directory

### Hosting path

The deployed files are expected to live physically in:

```text
/home/<cpanel-user>/public_html/cmdb
```

Because the FTP account is already rooted there, the workflow uploads into `/` from that account's perspective.

## 8. Cloudflare and FTP Constraint

This was a real issue in the setup and is important to preserve in documentation.

Problem:

- `ftp.sol-ventures.com` resolved through Cloudflare
- FTPS control connection on port `21` timed out
- GitHub Actions could not connect

Resolution:

- use the direct origin hostname from the hosting provider instead of the Cloudflare-proxied FTP hostname
- current working hostname: `s4377.lon1.stableserver.net`

Rule going forward:

- for FTPS deploys, prefer a direct server hostname that bypasses Cloudflare
- if a branded FTP hostname is used, it must not be Cloudflare-proxied

## 9. Build Behavior and Runtime Assumptions

The workflow builds with the following important values:

- `PUBLIC_URL=/cmdb`
- `CI=false`

### Why `PUBLIC_URL=/cmdb`

This ensures generated asset paths look like:

- `/cmdb/static/js/...`
- `/cmdb/static/css/...`
- `/cmdb/references/...`

Without this, the app would generate root-relative assets such as `/static/...`, which would break when the app is hosted in the `cmdb` subdirectory.

### Why `CI=false`

Create React App treats warnings as build failures in CI.
The current codebase still has lint warnings, so the workflow disables that failure behavior for deployment.

If the warnings are cleaned up later, this can be revisited.

## 10. Deployment Flow End to End

1. Developer merges or pushes a change to `main`
2. GitHub Actions starts the `Deploy to cPanel` workflow
3. The workflow checks required deploy secrets
4. Dependencies are installed with `npm ci`
5. The app is built with the required `REACT_APP_*` values and `PUBLIC_URL=/cmdb`
6. The static files in `build/` are uploaded to cPanel over explicit FTPS
7. Apache serves the app from `/cmdb/`
8. Unknown SPA routes are rewritten back to `/cmdb/index.html`

## 11. Verification Checklist After a Deployment

After every successful deployment, verify the following manually:

- `https://sol-ventures.com/cmdb/` loads successfully
- `https://sol-ventures.com/cmdb/assets` loads successfully
- hard refresh on `/cmdb/assets` does not return 404
- authentication redirects still return to `https://sol-ventures.com/cmdb`
- SharePoint-backed data still loads as expected

If any of these fail, review the troubleshooting section below.

## 12. Troubleshooting

### FTPS timeout on connect

Typical symptoms:

- `ETIMEDOUT`
- `control socket`
- cannot connect before authentication

Likely causes:

- FTP hostname is behind Cloudflare
- wrong FTPS hostname
- host firewall blocks external FTPS

Actions:

- verify `CPANEL_SERVER` points to the direct server hostname
- verify the host supports explicit FTPS on port `21`
- test the same credentials in a desktop FTP client if needed

### Missing GitHub secret

Typical symptom:

- workflow fails during the validation step before build or deploy

Action:

- add the missing repository secret in GitHub

### App loads but static assets 404

Likely causes:

- `PUBLIC_URL` is wrong
- deployment path is wrong
- app was uploaded to the wrong folder

Actions:

- confirm workflow still sets `PUBLIC_URL=/cmdb`
- confirm cPanel target folder is `public_html/cmdb`
- confirm `CPANEL_SERVER_DIR=/` only when the FTP account is rooted to `public_html/cmdb`

### Refreshing a deep link returns 404

Likely causes:

- `.htaccess` missing from the deployed build
- server rewrite rules not enabled

Actions:

- confirm `build/.htaccess` exists after build
- confirm `public/.htaccess` remains in the repo
- confirm Apache/LiteSpeed rewrite support is enabled in hosting

### Authentication redirects to the wrong URL

Likely cause:

- `REACT_APP_REDIRECT_URI` does not match the deployed path

Action:

- update the GitHub secret and the Azure app registration redirect URI if needed

### SharePoint integration fails after deployment

Likely causes:

- one or more `REACT_APP_*` secrets missing or stale
- wrong tenant or site URL
- wrong asset drive id

Actions:

- compare the GitHub secrets against the local working `.env`
- re-run the workflow after updating the secrets

## 13. Credential Rotation

When rotating credentials:

### FTP password

1. Change the password in cPanel for the deploy FTP account
2. Update `CPANEL_PASSWORD` in GitHub repository secrets
3. Re-run the workflow manually to verify the new credentials

### Azure or SharePoint values

1. Update the relevant `REACT_APP_*` repository secret
2. Re-run the workflow manually
3. Verify login and data access in production

## 14. Rollback Strategy

There is no separate artifact repository or release promotion flow yet.
Current rollback options are:

### Preferred rollback

- revert the bad commit on `main`
- push the revert
- let GitHub Actions redeploy automatically

### Emergency rollback

- manually replace the contents of `public_html/cmdb` from cPanel File Manager or an FTP client using a previously known-good build

## 15. Maintenance Notes

If any of the following change, this documentation and the workflow must be reviewed together:

- the production URL changes from `/cmdb/` to another path
- the hosting provider changes
- the FTP account root changes
- the app stops using `react-scripts`
- the deployment protocol changes from FTPS to another method
- a staging environment is introduced

Changes required if the app moves away from `/cmdb/`:

- update `PUBLIC_URL` in the workflow
- update `REACT_APP_REDIRECT_URI`
- update router paths if necessary
- update `public/.htaccess`
- update cPanel target directory if the physical location also changes
